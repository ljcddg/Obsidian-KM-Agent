# Obsidian-KM-Agent

> Obsidian 个人知识库管理系统 —— 不是 Writer，是 **Agent**

一个用于 **Claude Code / WorkBuddy** 的 Skill。当你说出「写笔记」「整理知识点」「建 MOC」「规划学习路线」「出面试题」时，它不会只生成一篇 Markdown 就结束，而是以 Agent 的方式接管知识库的**创建、分类、归档、索引、关系、复习**全流程，把 Obsidian 从「越攒越乱的笔记堆」变成「有层次、可检索、能复习的知识网络」。

本仓库内容是完整的 Skill，克隆后放入 `~/.claude/skills/`（Claude Code）或 `~/.workbuddy/skills/`（WorkBuddy）即可使用。

## 为什么需要它

| 痛点 | 本 Agent 的解法 |
|------|----------------|
| 笔记写完就沉底，越攒越乱 | 分类引擎自动归档，归入统一 Vault 目录，**禁止随意新建分类** |
| 重复笔记越写越多 | 创建前四层冲突检测，能扩展已有笔记就不新建（合并 / 子笔记 / 独立 / 关联） |
| 孤立节点无人问津 | 自动建立前置 / 相关 / 后续关系，双向补链，消除图谱里的孤立节点 |
| 学了就忘 | 生命周期状态（learning → mastered → review → archived）+ 间隔复习 + 面试模拟 |

## 核心能力（六大治理职责）

| # | 职责 | 说明 |
|---|------|------|
| 1 | **创建知识** | 按等级（L1/L2/L3）匹配模板，生成高质量笔记 |
| 2 | **分类知识** | 分类引擎：领域 → 一级 → 二级 → 层级 → 存储路径 |
| 3 | **归档知识** | 归入统一 Vault 目录，禁止随意新建分类 |
| 4 | **维护索引** | MOC 与 `.vault-meta/` 状态文件自动同步 |
| 5 | **管理关系** | 前置 / 相关 / 后续 + 双向链接 |
| 6 | **支撑长期学习** | 生命周期状态 + 间隔复习 + 面试模式 |

## 工作流程（Agent 循环）

每次任务完整走一遍，先理解你的知识库，再动手：

```
读取 Vault（目录 + .vault-meta 索引）
   ↓
分析结构（分类引擎：领域 / 分类 / 层级 / 路径）
   ↓
定位已有知识（重复检测：更新 / 子笔记 / 关联笔记）
   ↓
生成笔记（按等级匹配模板与要素）
   ↓
更新索引（MOC + .vault-meta + 双向链接）
   ↓
保存（写入文件，返回变更摘要）
```

## 笔记等级（内容深度的第一决策点）

| 等级 | 适用对象 | 内容量 | 必备要素 |
|------|---------|--------|---------|
| **L1 速记** | 单个 API、单个概念 | ≤ 1000 字 | 定义 + 核心机制 + 一个例子 |
| **L2 知识点** | 一个主题 | 1000~2500 字 | L1 + 为什么 + **实现原理** + 对比表 + 坑 + 自测 |
| **L3 专题** | 一个体系 | 2500 字以上 | L2 + MOC + mermaid + 学习路线 + 多篇关联 |

选级规则：一个方法 → L1；一个概念 → L2；一组有演进关系的概念 → L3。**拿不准就低不就高**。

> 💡 **面试导向**：技术主题的 L2/L3 笔记**必须写「实现原理 / 底层机制」**（数据结构 → 关键指令或方法 → 核心源码位置），不能只讲用法——`synchronized` 要答到对象头 Mark Word + monitorenter + ObjectMonitor，`CAS` 要答到 `Unsafe.compareAndSwapInt` + 自旋 + ABA。

## 特色能力

| 能力 | 触发时机 | 说明 |
|------|---------|------|
| **知识关系维护** | 每篇 L2/L3 写完后 | 自动扫描相关笔记，分类「前置 / 相关 / 后续」并双向补链 |
| **学习路线生成** | 「我要学 XX / 规划路径」 | 生成从基础到进阶的完整学习路径 |
| **事实验证** | 引用非用户素材的技术事实 | 按 A/B/C 级标注事实可信度，禁止编造无依据细节 |
| **面试复习模式** | 「出面试题 / 模拟面试 / 考前冲刺」 | 基于笔记生成面试题与模拟面试 |
| **架构锁定** | vault 分类变更 / 大规模迁移时 | 架构状态（stable / experimental / migration）+ 迁移方案 |
| **增量整合** | 创建任何新笔记前 | 四层冲突检测 + 关系分类 + 粒度判断 + 用户确认 |
| **修改权限** | 涉及 MOC / 索引 / 移动 / 合并时 | Level 0~3 四级权限 + 架构状态 × 操作白名单矩阵 |

## 安装

### 前置要求

- [Claude Code](https://claude.com/claude-code) **或** [WorkBuddy](https://www.workbuddy.cn/)（任一即可）
- Obsidian（建议，用于图谱与双链可视化）

### 安装步骤

**方式一：克隆仓库**

```bash
git clone https://github.com/ljcddg/Obsidian-KM-Agent.git
```

**方式二：下载 ZIP**

从仓库页面下载 ZIP 并解压。

然后，把 `obsidian-note-writer` 目录放入对应平台的 skills 目录：

| 平台 | 路径 |
|------|------|
| Claude Code（Windows） | `C:\Users\{{用户名}}\.claude\skills\obsidian-note-writer\` |
| Claude Code（macOS / Linux） | `~/.claude/skills/obsidian-note-writer/` |
| **WorkBuddy** | `~/.workbuddy/skills/obsidian-note-writer/` |

### 验证安装

重启 Claude Code / WorkBuddy，在对话中直接描述需求（如「帮我把这篇文档整理进知识库」），即可看到 Agent 接管工作流。

## 使用方式

### 触发场景

- 📝 「写一篇关于 XX 的笔记 / 整理这个知识点」
- 🗂️ 「把这篇文档收进我的知识库，归好类」
- 🕸️ 「为 XX 主题建一个 MOC / 图谱」
- 🧭 「我想学 XX，帮我规划一条学习路线」
- 🎯 「基于我的笔记出几道面试题 / 模拟面试」

### 示例对话

```
你：把这份「Java 并发」笔记收进我的知识库，顺便看看有没有重复的
Agent：
  分类引擎：CS / Java / Concurrent / JDK API → 数据结构/5-并发多线程/
  冲突检测：候选 [[CompletableFuture.md]]（L1+L4 双高）→ 判定 B 同节点扩展，建议子笔记
  等级：L2 知识点
  ... 写入笔记，更新 MOC 与 .vault-meta，双向补链 ...
  ✅ 变更摘要：新建 X / 更新 MOC / 同步索引
```

## 项目哲学

- **三层管理**：目录（物理层）+ frontmatter 元数据（元数据层）+ 双向链接（关系层），三层必须一致。
- **不重复造轮子**：创建任何新笔记前先做冲突检测，能扩展已有笔记就不新建。
- **不编造事实**：技术事实按可信度分级标注（A 官方文档 / B 权威书籍 / C 博客），无法确认的标 `❓待验证`。
- **面试导向**：技术主题的笔记必须讲清「为什么这么实现」，不只讲「怎么用」——实现原理是 L2/L3 的必写要素。
- **生命周期驱动**：知识从学习到掌握到归档，配合间隔复习，确保笔记被真正用起来。
- **尊重用户习惯**：已有分类体系优先复用；涉及移动 / 合并 / 大规模变更，先列清单征得确认再动手。

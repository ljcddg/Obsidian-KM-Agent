# Workflow · Analyze（需求分析）

写作前必须完成的决策：**分类引擎 → 定等级 → 定主线 → 定素材 → 重复检测**。分类引擎见 `workflow/classify.md`，本文负责后四项。不要跳过直接开写。

## Step 1 · 定笔记等级

回答两个问题：

1. **内容对象是什么？**
   - 单个 API / 单个函数 / 一个结论 → **L1 速记**
   - 一个概念（带机制、有易混点）→ **L2 知识点**
   - 一组有演进/依赖关系的概念 → **L3 专题**

2. **读者目标是什么？**
   - 只需"知道有这东西" → L1
   - "要能讲清楚原理并应付提问" → L2
   - "要建立体系、能给别人讲" → L3

等级决定内容量与要素清单（见 `SKILL.md` 一、笔记等级），**宁可写短一点，不要注水**。

## Step 2 · 定主线类型

| 主线 | 适用 | 结构 |
|------|------|------|
| 演进线 | 系列概念有前后依赖 | 基础 → 问题 → 升级方案 → 对比 |
| 分层线 | 从整体到细节 | 总览 → 各层/各部件 → 串起来 |
| 流程线 | 讲过程/机制 | 输入 → 步骤 1..n → 输出 → 边界情况 |
| 对比线 | 多个易混对象 | 各自介绍 → 对比表 → 怎么选 |

L1 不需要主线；L2 选一种；L3 可组合（如演进线 + 对比线）。

## Step 3 · 定素材与查证（来源可靠性规则）

**素材来源优先级，按序采用，不跳过：**

| 笔记类型 | 优先 | 其次 | 最后 |
|---------|------|------|------|
| 技术类（语言/框架/API） | 官方文档 | 源码 | 权威博客/教程 |
| 理论类（算法/学科概念） | 论文/教材 | 官方教材配套资料 | 权威公开课/百科 |
| 用户自带素材（代码/文档/旧笔记） | 全部通读提炼 | 需要时用上述规则补证 | — |

**强制规则：**
- **禁止无依据的补充细节**。凡是官方文档/源码里没有的内容，不得编造参数、行为、版本特性。
- 技术事实按可信度分级标注：A 级（官方文档/源码/JDK 注释）直接写；B 级（权威书籍）注明来源；C 级（博客）标注来源；**无法确认的标 `❓待验证`**（完整规则见 `features/fact-check.md`）。
- 用户给的是代码时：先读代码提炼真实行为，**不要凭印象猜**；拿不准的 API 行为去查文档确认。
- 涉及版本差异（如"XX 版本以后..."）必须标注版本号，并在 frontmatter 记录环境版本（见 `references/coding-note.md`）。
- 引用的结论可注明来源（文档链接/类名+行号），便于日后复核。

## Step 4 · 创建前冲突检测（增量知识整合）

**每次创建笔记前，执行 `features/conflict-detection.md` 的完整检测流程。** 不是简单搜文件名，而是四层检测 + 粒度判断：

1. 预筛候选（index.json 或 Grep，缩小范围到 Top 5~10 篇相关笔记）。
2. 四层检测：L1 文件名/标题重合 → L2 tags/category 交集 → L3 [[ ]] 关联链 → **L4 核心概念词语义重叠度**（关键）。
3. 关系分类：
   - **A. 同节点重复**（核心概念一致 + 深度相同）→ 建议合并
   - **B. 同节点扩展**（同一知识节点不同维度，如"使用"+"源码"）→ 建议子笔记
   - **C. 不同层级**（交集但体量/角度差异大）→ 独立保存 + 关联
   - **D. 弱相关** → 仅关联链接
4. 粒度判断：合并后是否超过体量上限（L2 ≤2500 字 / L3 ≤5000 字）→ 超过自动判 C。

**输出格式：** 在写作计划中以"冲突检测"行展示候选笔记 + 原因 + 推荐方案（A/B/C/D），**等待用户确认后再新建**。

示例：
```
冲突检测：候选 [CompletableFuture.md]（L1+L4 双高）→ 新内容侧重源码，已有侧重 API
判定：B 同节点扩展（合并后不超 L2 上限）
建议：创建子笔记 [[CompletableFuture源码解析]]，原笔记补"详见"链接
```

## Step 5 · 检查已有知识（防孤立笔记）

- 用核心概念词搜索 vault，确认是否已有相关笔记（前置/相关/后续）。
- 已存在则写完后走 `features/knowledge-map.md` 建关系链接，避免产生孤立节点。

## 输出产物

写正文前，先输出一段简短的"写作计划"（3~5 行）供确认：

```
分类引擎：CS / Java / Concurrent / JDK API → 数据结构/5-并发多线程/
等级：L2 知识点
主线：演进线（A → 为什么需要 B → 对比）
素材：用户提供的 Demo 代码 + 官方文档补证（事实分级：A 级为主）
冲突检测：候选 [[CompletableFuture.md]]（L1+L4 双高）→ 判定 B 同节点扩展，建议子笔记
结构：痛点开头 / 为什么 / 机制 / 对比表 / 坑 / 自测
关系：前置 [[X]] / 相关 [[Y]] / 后续 [[Z]]
```

需求模糊（体量/受众不清）时，先问清楚再继续，不要猜着写。

# Feature · Fact Check（事实验证，防知识库中毒）

> 目标：给知识库里的每个事实标注**可信度级别**，把"可能是对的"和"确认是对的"区分开，防止几年后知识库积累错误知识。

## 触发时机

写作时引用任何**非用户提供素材**的技术事实；用户素材中的结论拿不准时同样适用。

## 技术事实分级（写入笔记时标注）

| 级别 | 来源 | 写作时的处理 |
|------|------|-------------|
| **A 级** | 官方文档 / 源码 / JDK 注释 / 官方 JEP | 可直接写入，不标注 |
| **B 级** | 权威书籍（如《Java 并发编程实战》）、官方教程 | 可写入，重要处注明来源书名 |
| **C 级** | 博客 / 论坛 / 经验贴 / 培训资料 | 谨慎采用；写入时标注 `来源：{{来源}}` |
| **❓ 待验证** | 无法确认 / 多方说法冲突 / 记忆模糊 | 必须标记 `❓待验证`，不得当确定事实写 |

## 强制规则

1. **无法确认的事实 → 标 `❓待验证`**，绝不裸写。
2. 版本相关结论必须带版本号（见 `references/coding-note.md` 环境规范）。
3. 引用源码结论时写类名 + 方法名，方便复核（如 `HashMap#putVal`）。
4. 同一个事实在 C 级来源与官方文档冲突时，以官方为准，并在笔记里注明差异。
5. 复习时遇到 `❓待验证` 标记 → 优先去官方文档核实，核实后升级为 A/B 级并删标记。

## 标记规范

```markdown
- {{结论}}（A 级，见 `java.util.concurrent.CountDownLatch#await`）
- {{结论}}（C 级，来源：某博客，2024-xx）
- {{结论}}（❓待验证：JDK 21 行为待确认）
```

## 定期复核

- 每次复习笔记时（见 `workflow/review.md`），顺手清一遍 `❓待验证` 标记。
- 大版本升级（如 JDK 8 → 21）后，扫描知识库中标注旧版本号的事实，核对是否过时。

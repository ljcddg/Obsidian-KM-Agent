# Feature · Conflict Detection（知识冲突检测与增量整合）

> 目标：**创建笔记前先理解已有知识，而不是盲目生产新文件。** 大规模知识库真正的问题不是没有新知识，而是旧知识越来越多以后无法保持结构稳定。本模块执行四层检测 + 关系分类 + 粒度判断，让每次新增都是"精准嵌合"而非"野蛮堆积"。

## 触发时机

创建任何新笔记前自动执行。analyze.md 的"重复检测"步骤统一调用本模块。

## 执行流程

### Step 1 · 候选集预筛（用索引快速过滤，避免全库扫描）

有 `.vault-meta/index.json` → 用它预筛候选（按 tags/related/category 交集筛选，Top 5~10）。
无索引 → 用 Grep 搜文件名 + 一级标题 + frontmatter tags，范围缩小到核心概念词。

预筛标准：
- 文件名/标题与新知识核心概念词有 ≥50% 词重合
- 或 frontmatter tags/related 有交集
- 或位于同一 category/subcategory 下

### Step 2 · 四层检测（逐层深入，非一刀切）

| 层 | 检测内容 | 工具 | 权重 |
|---|---------|------|------|
| **L1 文件名/标题** | 新旧笔记名/标题的字符与词重合度 | 文件名对比 + title frontmatter | 高 |
| **L2 元数据** | tags / category / subcategory / related 的交集 | frontmatter 字段匹配 | 中 |
| **L3 关联链** | 新知识的概念词，在已有笔记的 [[ ]] 链接中出现了几次 | Grep 搜索 [[链接]] | 中 |
| **L4 核心概念语义** | 新旧内容的核心概念词（2~8 个）覆盖重合率 | 正文关键词提取 + 对比 | 最高 |

**综合判断阈值：**
- L1 高 + L4 高 → 大概率同主题，深入检测
- L1 低 + L4 高 → 可能不同角度写同一概念，需确认
- 仅 L2 命中（同分类不同主题）→ 弱相关

### Step 3 · 关系分类（不是"有重复就合并"，是粒度判断）

| 关系 | 判定标准 | 建议动作 |
|------|---------|---------|
| **A. 同节点重复** | 核心概念完全一致，内容覆盖 ≥70%，属同一知识深度 | 建议合并到已有笔记 |
| **B. 同节点扩展** | 同一个知识节点的不同维度（如 HashMap 基础 已有，新的是 HashMap 源码），共用同一个核心概念词 | 建议作为子笔记，原笔记补"详见 [[子笔记]]" |
| **C. 不同层级** | 概念有交集但属于不同知识层级（如"Java并发"专题 已有，新的是"CompletableFuture"知识点），体量或角度差异大 | 独立保存，建立双向链接（前置/相关/后续） |
| **D. 弱相关** | 仅 tags/分类有交集，核心概念无关 | 仅建立 [[关联链接]]，无需合并 |

**粒度判断核心规则：**
- **"同一知识节点"的判断标准**：如果新旧内容合并后可以自然地放在一个 L2/L3 笔记里，且不会超过该等级体量上限（L2 ≤2500 字，L3 ≤5000 字），则属于同一节点 → 走 A 或 B。
- **超过体量上限 → 自动判 C**（不同层级，分开更健康）。
- **"Redis.md" 与 "Redis源码.md" 判 C，不判 B**——因为 Redis 源码分析本身可以是一篇独立的 L2/L3（体量通常超过 L2 上限），不应塞成子笔记。

### Step 4 · 输出决策（展示给用户，请确认）

在写作计划的"重复检测"行输出：

```markdown
冲突检测：
- 候选：[CompletableFuture.md]（L2，文件名+核心概念词 L1+L4 双高）
- 新内容侧重：[源码实现 / 异步编排流程]，已有内容侧重：[API 使用 / 概念介绍]
- 判定：B 同节点扩展（同一知识节点不同维度，合并后不超过 L2 上限）
- 建议：创建子笔记 [[CompletableFuture源码解析]]，原笔记补"详见"链接
- 备选：A 直接合并（若你希望一篇搞定）
```

**等待用户确认后再新建**，不要自行决定合并/拆分的具体方式。

### Step 5 · 冲突后的维护

- 选择 A（合并）→ 更新原笔记 frontmatter `updated`，追加版本演进说明。
- 选择 B（子笔记）→ 新建子笔记，原笔记补 `related` 与 [[ ]] 链接，两篇都更新 MOC。
- 选择 C（独立）→ 走 `features/knowledge-map.md` 建双向关联。
- 选择 D（仅链接）→ 在"关联笔记"小节加一行即可。
- 所有动作同步 `.vault-meta/index.json` 与 `changelog.md`（如有）。

## 与 analyze.md 的分工

- `analyze.md` Step 4 "重复检测"：负责调用本模块，三选一（更新/子笔记/关联）变为基于检测结果的四选一（A/B/C/D），产出写作计划中的"冲突检测"行。
- `conflict-detection.md`（本文）：负责检测逻辑、阈值、粒度判断、输出格式。

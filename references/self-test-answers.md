# Reference · 自测题答案规范：写作 / 隐藏 / 样式

> 本规范回答三件事：**答案怎么写**（内容与版式）、**怎么隐藏**（Obsidian 折叠）、**怎么设样式**（CSS 定制）。
> 适用范围：一切"带答案的自测题"。开放式（无答案）系列不适用。
> 配套资产：`assets/自测答案样式.css`（可直接分发使用）。

---

## 〇、总原则（先读）

1. **形态跟随系列**：动笔前翻该分类下最近一篇成熟笔记的自测题，开放式 / 折叠式**跟随它**；同一篇内**不许混搭**。
2. **带答案必须给全**：一篇里所有题号都要有对应答案，不许只给几题。
3. **答案只从正文提炼**：数值、公式、代码引用必须与笔记正文一致，**禁止另编**；正文没有的结论不许写进答案。
4. **答得出才算学过**：答案是为了闭卷自测后对照，不是"把正文再抄一遍"——能一句话讲透机制本质的，不写两段。

---

## 一、怎么写答案（内容与版式）

### 1.1 版式铁律：一点一行，不许串在一行

答案在折叠区里**逐点成行**（`> - ` 列表），禁止用 `① ② ③` 把整段答案挤在一行——展开后没法扫。

❌ 坏例子（挤一行，难扫）：

```markdown
> [!answer]- 参考答案（点击展开）
> 三步：① 应用把方法生成 JSON Schema 放进请求 ② 模型返回 tool_calls 只声明不执行 ③ 应用执行并回喂结果。模型"知道"是因为每次请求都带全量 schema。
```

✅ 好例子（一点一行，顺着读就是逻辑顺序）：

```markdown
> [!answer]- 参考答案（点击展开）
> - ① 应用把 `@Tool` 方法生成 **JSON Schema**，放进请求的 `tools` 数组随消息发给模型
> - ② 模型判断"该不该调、传什么参"，返回 `tool_calls`（工具名 + 参数，**只声明不执行**）
> - ③ 应用真正执行方法，把结果作为 tool 消息**回喂**模型，模型基于结果生成最终回答
> - 模型"知道"有哪些函数 = 每次请求的 `tools` 都带着全部函数 schema
```

### 1.2 拆分粒度规则

| 答案类型 | 怎么拆 | 示例 |
|---------|--------|------|
| 流程 / 步骤类 | 一个环节一行，行序 = 执行顺序 | 三步握手：① SYN → ② SYN+ACK → ③ ACK |
| 辨析类（A vs B） | A 是什么一行、B 是什么一行、差异结论一行 | 各管一摊：ChatHistory 管清单、ChatMemory 管内容 |
| 要点 / 列举类 | 一个要点一行 | 三个原因分别成行 |
| 带代码的 | 代码内联保留在对应要点行里 | `switch (m.getMessageType()) { case USER -> "user"; ... }` |

### 1.3 其他写作要点

- **要点加粗**：每行的关键结论 / 关键术语加粗（`**JSON Schema**`），扫答案时重点还在。
- **删除总起词**：列表化后，"三步：""四个 default："这类总起词冗余，删掉（把数量写进行首 `① ② ③` 即可）。
- **半句到一句讲清**：一个要点能一句话讲透的，不写两句。
- **不用"参考答案里再提问"**：答案直接给结论，不要反问读者。

## 二、怎么隐藏（Obsidian 折叠）

### 2.1 原理：Obsidian callout 的折叠开关

Obsidian callout 标题后加 **`-`**（减号）= 默认折叠，点击标题才展开：

```markdown
> [!note]- 我是折叠标题（默认收起）
> 我是内容，点标题展开后可见
```

`+`（加号）= 默认展开；不带符号 = 始终展开。隐藏答案用 **`-`**。

### 2.2 两种布局，按系列选一种

**布局 A：一题一折叠（默认推荐）**——题目读完紧跟它自己的答案，节奏好、对照方便：

```markdown
### 基础题（1-5）

1. **Function Calling 的三步流程是什么？大模型是怎么"知道"有哪些函数可调的？**

> [!answer]- 参考答案（点击展开）
> - ① 应用把 `@Tool` 方法生成 **JSON Schema** 放进请求 `tools` 数组发给模型
> - ② 模型判断"该不该调、传什么参"，返回 `tool_calls`（**只声明不执行**）
> - ③ 应用真正执行方法，把结果作为 tool 消息**回喂**模型，模型据此生成最终回答
> - 模型"知道" = 每次请求 `tools` 都带全量函数 schema

2. **`@Tool` 和 `@ToolParam` 分别标注什么？不打 `@ToolParam` 会有什么后果？**

> [!answer]- 参考答案（点击展开）
> - `@Tool` 标在 public 方法上，声明"这是一个可被模型调用的工具"
> - `@ToolParam` 标在方法参数上，给参数写描述
> - **不打 `@ToolParam`** → 模型只能靠参数名猜语义，传参准确率大幅下降
```

**布局 B：整体折叠**——题目 1~N 连着列完，篇末一个整体 callout 按题号给答案：

```markdown
1. **...？**
2. **...？**
3. **...？**

> [!answer]- 参考答案（点击展开）
> 1. 答案...
> 2. 答案...
> 3. 答案...
```

> 布局选择：**跟随该系列最近一篇成熟笔记**。若系列无先例，默认布局 A。
> 智能客服、RAG 等 12-SpringAI 系列笔记采用的是布局 A + `[!answer]`。

### 2.3 callout 类型用哪个：`[!answer]` vs `[!question]`

| 类型 | 语义 | 默认外观 | 是否可被专属样式定制 |
|------|------|---------|---------------------|
| `[!question]` | 提问 / 思考 | 蓝紫（随主题） | 会和真正的提问区撞样式 |
| `[!answer]` | 参考答案 | 随主题默认 | **建议**：配 `assets/自测答案样式.css` 后独享 teal 青配色，与提问区一眼区分 |

- **推荐用 `[!answer]`**：语义化（这是答案不是问题），且 CSS 能精准选中 `data-callout="answer"` 定制，不会误伤别处提问用的 `[!question]`。
- 不挂 CSS 时 `[!answer]` 也能正常折叠，只是颜色走主题默认——**功能不依赖 CSS**。

### 2.4 禁区：禁用 `<details>` / `<summary>`

Obsidian 里**不要**用 HTML `<details>` 做折叠——它对 `<summary>` 后的空行敏感，遇空行会拦腰截断 HTML 块，导致 `<details>` 变空容器、答案跑到折叠区外"一直展开"；且内部 markdown（加粗 / 行内代码）不渲染。**一律用 callout 折叠**（§2.1），原生、稳定、支持 markdown。

## 三、怎么设样式（CSS snippet）

### 3.1 为什么需要 CSS

Obsidian 内置 callout 外观由主题决定，字体、颜色没人管。要让答案区"像注释层"（小一号、次级色、teal 青、展开后不抢正文），需要 CSS 代码片段（snippet）。

### 3.2 挂载三步

1. **放文件**：把 skill 资产 `assets/自测答案样式.css` 复制到 vault：
   ```
   {{vault}}/.obsidian/snippets/自测答案样式.css
   ```
   （若 `.obsidian/snippets/` 不存在则新建。）
2. **启用**：编辑 `.obsidian/appearance.json`，把片段名加进 `enabledCssSnippets`：
   ```json
   {
     "enabledCssSnippets": ["自测答案样式"]
   }
   ```
   或在 Obsidian **设置 → 外观 → CSS 代码片段** 里手动打开开关。
3. **生效**：Obsidian 会自动监听 snippet 文件；启用列表的变更通常要 **重启 Obsidian** 才吃到。重启后答案折叠区即变 teal 青。

### 3.3 微调三处（改一个文件即可）

```css
.callout[data-callout="answer"] {
  --callout-color: 20, 184, 166;   /* ① 主色：RGB 三元组（teal-500）。换 0,122,255 即变蓝 */
}
.callout[data-callout="answer"] .callout-content {
  font-size: 0.92em;               /* ② 答案字号：1em = 正文大小 */
  color: #5b6470;                  /* ③ 答案文字颜色（浅色主题）；深色主题走 --text-muted */
}
```

- 主色影响：折叠标题字色、左边框、图标。`--callout-color` 只收 **RGB 三个数字**，不带 `#` 不带括号。
- 图标可用任意 [lucide 图标名](https://lucide.dev)：`--callout-icon: lucide-badge-check;`。
- 想让"加粗要点"不被浅色削弱，保留这条规则：
  ```css
  .callout[data-callout="answer"] .callout-content strong { color: var(--text-normal); }
  ```

### 3.4 不想用 CSS 怎么办

不挂任何 snippet，折叠照样工作（见 2.3 表）。CSS 只是"好看"，不是"能用"的前提。若库里别的笔记用 `[!question]` 做答案区且不打算统一，就维持原状，**不强行改类型**（跟随系列优先）。

## 四、完整样例（可直接套用）

```markdown
## 十五、自测题

### 基础题（1-3）

1. **XXX 为什么需要 A？**

> [!answer]- 参考答案（点击展开）
> - 核心矛盾：**{{不解决会怎样}}** → 需要一个 {{机制}} 兜底
> - {{一句话讲透机制本质}}

2. **辨析：A 与 B 的区别？**

> [!answer]- 参考答案（点击展开）
> - A：{{是什么、管哪摊}}
> - B：{{是什么、管哪摊}}
> - 结论：{{各自适用场景 / 怎么选}}

3. **场景题：XX 场景用哪个，为什么？**

> [!answer]- 参考答案（点击展开）
> - 选 {{X}}，因为 {{理由，联系正文机制}}

---
```

> 收尾完整结构：… → 踩坑提醒 → **自测题（N 道）** → 相关笔记。
> 写完用 `workflow/review.md` 过门禁。

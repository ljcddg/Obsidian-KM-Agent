# Workflow · Classify（自适应知识架构引擎）

> 目标：**先理解用户的组织方式，再决定怎么归档**。本引擎不假设任何固定目录结构——它感知项目现状，输出最佳策略（复用 / 优化 / 新建），然后落地。目录只是物理组织的一层，配合 tags / metadata / 链接 / MOC / 索引形成"三层管理"。

## Step 0 · 架构感知（Architecture Aware，生成笔记前必做）

读项目目录结构，回答五个问题，决定策略：

| 问题 | 判断依据 | 影响 |
|------|---------|------|
| 已有分类体系？ | 读目录 + frontmatter category/tags | 有 → A 复用 / B 优化；无 → C 新建 |
| 分类合理吗？ | 层级 ≤3、命名一致、无大量 "inbox" 笔记 | 合理 → A；混乱 → B |
| 知识库规模？ | 笔记数 ≤20 vs 20~100 vs 100+ | 小 → 灵活；大 → 谨慎 |
| 使用模式？ | 学习 / 项目文档 / 技术文档 / 研究 | 影响分类粒度与目录风格 |
| 架构状态？ | stable / experimental / migration（见 `features/architecture.md`） | stable → 禁止随意重构；experimental → 允许调整 |

## Step 1 · 三选一策略

### A. 复用已有结构（默认首选）

**触发条件**：用户已有成熟分类体系，且层级 ≤3、命名一致。

**动作**：
- 分析输入内容 → 归入最匹配的已有子目录。
- frontmatter `category`/`subcategory` 沿用现有约定。
- 绝不创建新目录；放不下时提"是否扩展已有目录"的建议。

### B. 优化已有结构

**触发条件**：存在分类但发现问题——层级过深、重复严重、命名不一致、大量散落笔记。

**动作**：
- 列出优化建议清单（如"3-概率结构 和 2-树形结构 可合并为 2-数据结构"），一次只提 2~3 条，不一次性大改。
- 标记当前的 `architecture_status: migration`（见 `features/architecture.md`），迁移完成后恢复 `stable`。
- 涉及文件移动 → 先列受影响笔记清单，征得确认。

### C. 创建新结构

**触发条件**：全新 vault 或当前分类完全不符合需求。

**动作**：根据使用模式推荐初始结构，一次只建 2~4 个子目录，命名 `编号-分类名/`：

| 使用模式 | 初始结构建议 |
|---------|-------------|
| 学习型 | `计算机科学/` `面试/` `归档/` |
| 项目文档 | `需求/` `设计/` `实现/` `测试/` |
| 技术文档 | `架构/` `API/` `运维/` `备忘录/` |
| 研究型 | `论文/` `概念/` `实验/` `笔记/` |

- 标记 `architecture_status: experimental`，后续可随需求调整。
- 绝不创建超过 4 个一级目录（初始够用即可，多了是过度设计）。

## Step 2 · 三层管理（目录只是第一层）

分类引擎归好目录后，同时补上另外两层：

| 层 | 工具 | 作用 |
|---|------|------|
| **物理层** | 目录 + 文件名 | 快速定位，文件浏览器可见 |
| **元数据层** | frontmatter（tags/category/subcategory/domain/level）| 多维度检索，Dataview 可用 |
| **关系层** | [[ ]] 双向链接 + MOC + .vault-meta 索引 | 知识网络，Agent 可达 |

三层必须一致：`category` = 所在目录、`tags` 覆盖目录关键词、`[[ ]]` 连到相关笔记与 MOC。

## Step 3 · 分类决策优先级

冲突时按此优先级裁决：

1. **用户已有分类规则**（最高优先，尊重习惯）
2. **项目领域最佳实践**（如 Java 项目按包名组织「并发/JVM/集合」）
3. **AI 推荐结构**（最后参考，仅当以上两者不可用）

若三者冲突 → 向用户说明理由，不擅自做决定。

## 输出产物

写作计划中必须包含：

```
架构感知：学习型 vault，已有 5 个分类子目录，状态 stable → 策略 A 复用
分类引擎：CS / Java / Concurrent / JDK API → 5-并发多线程/
三层管理：目录 5-并发多线程/ + tags [Java,并发] + 链接 [[Java并发编程面试题集]]
重复检测：无同名 → 新建
```

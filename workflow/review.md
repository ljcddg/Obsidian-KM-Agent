# Workflow · Review（自检 + 复习闭环）

写作完成后执行两步：**质量自检**（保证笔记合格）→ **补复习信息**（保证笔记被真正用起来）。

## Step 1 · 质量自检（按等级过门禁）

### L1 速记
- [ ] 定义是否 1~2 行讲清？
- [ ] 核心机制是否配了一个例子？
- [ ] 有没有超出 L1 体量（≤1000 字）？

### L2 知识点
- [ ] 开头是否回答了"为什么学这个/这有什么用"？
- [ ] "为什么需要"是否比"是什么"篇幅更大？
- [ ] **是否讲清实现原理/底层机制**（数据结构 / 关键指令或方法 / 源码位置，至少一个层面展开）？
- [ ] 易混点是否都有对比表？
- [ ] 是否写了至少一个"别人常踩的坑"？
- [ ] 自测题是否覆盖本篇所有小节（含实现原理）？
- [ ] 有没有编造无依据的细节（对照来源查证规则）？

### L3 专题
- [ ] 是否全部满足 L2 门禁？
- [ ] 是否有 mermaid 图 + 文字解读？
- [ ] 是否有学习路线（先读哪篇 → 后读哪篇）？
- [ ] 是否已建/已接入 MOC，并给相关旧笔记补了反链？

### 通用
- [ ] 文件名是否符合 `{{主题}}知识点.md` / `{{主题}}速查.md` 约定？
- [ ] frontmatter 是否完整（title/tags/category/created/updated/复习字段）？

## Step 2 · 补复习信息（生命周期闭环）

每篇笔记 frontmatter 必须包含生命周期字段（完整规范见 `references/learning-system.md` 与 `references/vault-meta.md`）：

```yaml
---
status: learning            # 生命周期：learning / mastered / review / archived
importance: ⭐⭐⭐⭐          # 重要程度 1~5 星
created: YYYY-MM-DD         # 首次创建
updated: YYYY-MM-DD         # 最近修改
review_date: YYYY-MM-DD     # 下次复习日期
---
```

**间隔复习节奏（按重要程度）：**
- ⭐⭐⭐⭐⭐：1 天 → 3 天 → 7 天 → 15 天 → 30 天 → 60 天
- ⭐⭐⭐⭐：3 天 → 7 天 → 15 天 → 30 天 → 60 天
- ⭐⭐⭐：7 天 → 30 天 → 90 天
- ⭐⭐ 及以下：30 天一次即可，或归档

**生命周期流转（每次复习一档）：**
```
learning → mastered（能闭卷讲清楚）→ review（长期复习轮）→ archived（移入项目归档目录）
自测答不出 → 状态降一级，间隔重置
```

**复习动作**：重读笔记 → 默写自测题答案 → 更新 `status` 与 `review_date` → 把"还能错的坑"补进笔记 → 同步 `.vault-meta/index.json`。

## Step 3 · Obsidian 生态整合（L2/L3 必做）

1. **双向链接**：文末加"关联笔记"小节（前置/相关/后续），用 `[[文件名]]` 链接并写清关联理由；去相关笔记末尾补一条反链。
2. **MOC**：L3 或新主题起 `MOC-{{主题}}.md`（放项目根或就近），新增笔记后走 `workflow/maintain.md` 自动同步。
3. **物理归档**：按项目分类移入对应目录，并确保 Obsidian 已开启链接跟随设置（见 `references/obsidian.md` 第三节）。
4. **标签一致性**：frontmatter 的 `tags`/`category`/`subcategory` 与文件夹结构保持一致。

# 复习系统规范（知识生命周期管理）

> 笔记只是载体，**复习才是知识库的造血机制**。本规范让每篇笔记拥有完整的生命周期：创建 → 学习 → 掌握 → 复习 → 归档。

## 1. 生命周期状态机

```yaml
learning（学习中，新笔记默认）
  ↓ 复习通过 1~2 次
mastered（已掌握：能讲解，进入常规复习排期）
  ↓ 长期间隔 ≥ 60 天
review（复习中：达到长期间隔，回归复习清单）
  ↓ 再次确认
archived（已归档：移入项目归档目录，如 _archive/，不再排期）
```

| 状态 | 含义 | 默认动作 |
|------|------|---------|
| `learning` | 刚创建，还没复习过 | 排近期复习（1~7 天） |
| `mastered` | 能闭卷讲清楚 | 按间隔正常复习 |
| `review` | 进入长期复习轮 | 每次复习后评估 |
| `archived` | 长期掌握 | 移入项目归档目录（如 `_archive/`） |

- **状态回退**：自测答不出 → 状态降一级，间隔重置为当前级第一档。
- **状态变更**：更新 frontmatter `status` + `review_date`，必要时移动文件。

## 2. frontmatter 生命周期字段

```yaml
---
status: learning              # learning / mastered / review / archived
created: YYYY-MM-DD           # 首次创建
updated: YYYY-MM-DD           # 最近修改
review_date: YYYY-MM-DD       # 下次复习日期
importance: ⭐⭐⭐⭐            # 重要程度 1~5 星
---
```

**重要性评估规则：**
- ⭐⭐⭐⭐⭐：面试高频 / 核心原理，必背。
- ⭐⭐⭐⭐：常用且易混，需能讲清。
- ⭐⭐⭐：理解即可，偶尔用到。
- ⭐⭐ 及以下：速记级，归档。

## 3. 间隔复习节奏

按 `importance` 决定初始间隔，每次复习后按档递进：

| 重要程度 | 复习序列（天） |
|---------|---------------|
| ⭐⭐⭐⭐⭐ | 1 → 3 → 7 → 15 → 30 → 60 |
| ⭐⭐⭐⭐ | 3 → 7 → 15 → 30 → 60 |
| ⭐⭐⭐ | 7 → 30 → 90 |
| ⭐⭐ | 30 → 归档 |

- 复习日期 = 本次复习日 + 下一档间隔。
- 连续两轮"能讲解"且间隔 ≥ 60 天 → `mastered` → `archived` 流程。

## 4. 掌握状态递进（辅助 `status` 细粒度评估）

```
理解（看得懂）
  ↓ 复习 1~2 次
能手写（能默写核心机制/代码）
  ↓ 复习 2~3 次
能讲解（能给别人讲清楚，含为什么）
```

- 复习时**先闭卷自测**（盖住笔记回想），再对照订正。
- 自测题答不出 → 状态降一级，间隔重置为该级第一档。

## 5. 复习动作清单

每次复习执行：

1. 重读笔记（30 秒~3 分钟）。
2. 闭卷默写自测题答案 / 核心机制流程。
3. 对照订正，把"还能错的坑"补进笔记（笔记随复习进化）。
4. 更新 `status`、`review_date`（按间隔节奏），必要时移动文件（archived → 项目归档目录，如 `_archive/`）。

## 6. 与 Obsidian 插件配合（可选增强）

| 插件 | 用途 |
|------|------|
| **Dataview** | 自动聚合 `review_date` 字段，生成"今天该复习哪些"清单 |
| **Spaced Repetition** | 把笔记内容做成卡片式闪卡，自动排期 |
| **Templater** | 一键插入生命周期字段与模板 |

Dataview 示例查询（放一张"今日复习"笔记里）：

```dataview
TABLE status, importance, review_date
FROM #笔记
WHERE review_date <= date(today)
SORT review_date ASC
```

## 7. 归档规则

- `status: mastered` 且间隔 ≥ 60 天 → 标记 `archived: true`，移入项目归档目录，从复习清单移除。
- 归档笔记保留在知识库中作为索引，不再排期。
- 新场景用到时随时复活，重新排期。
- 归档/复活时同步更新 `.vault-meta/index.json` 与 `changelog.md`（见 `references/vault-meta.md`）。

**核心思想**：知识库不是"写完就结束"的仓库，而是"越复习越强"的系统——每篇笔记都应能回答"我处于生命周期的哪个阶段、什么时候再来看它"。
